# Design

## Background
与另一个 change 的关系：两个 change 同时进行（`2026-10-27-sampler-clip-cap` 在 A 机，`2026-10-27-mixed-precision` 在 B 机），文件不重叠。

- 论文 Fig. A.1 精确读数：单卡 H100 约 9.5 次/s，3 h ≈ 100k 次迭代。
- 我们和论文有两个独立的差距：
  1. 同迭代下失败数约是论文的 2 倍（44k：166–210 对 103；88k：67–82 对约 30）；
  2. 速度慢约 4 倍（2.3 次/s 对 9.5 次/s）。
- 两条路线各对应一个差距。
- 后期退化不在这两个 change 的范围内，等采样器的结果出来再看。目前的数据（随机 2000 个片段的子集评测）：
  - 新 run：104k 0.9401 → 120k 0.9244 → 136k 0.9160，下降从 104k 到 120k 之间开始；
  - B 对照：104k–112k 保持在 0.942–0.944，123k 时停掉。

- 回报采样的困难部分占全部重置的 40%，按论文 D.1 的 softmax_b(−25·G_b) 分配，BONES-SEED 上约有 101 万个 bin。
- 从 checkpoint 里的 `bin_return` 还原（`bones_seq_critic_alive@A` 和 `bones_seq_sampler@A`）：
  - 20k–148k 之间，困难质量的 76–96% 一直落在 `kick_back_001` 的少数 bin 上。这些 bin 的 G ≈ 0.23，整个训练期间都没有提高；
  - 有效 bin 数只有 2–5 个，有效动作类别数约 1.1 个；
  - 新 run 在 146k 时困难质量转到 `kneeling_start_001` 的一个 bin（G 0.10，占困难质量 86%），训练回报跌到 0.07，之后才恢复；
  - 旧 A 在 144k 时一度 99% 集中在 `hook_jump_off_wall_R_003__A304_M`。
- 评测中失败的那些片段，失败位置所在 bin 的训练 G 中位数是 0.844（全部 bin 中位数 0.958），大约排在最难的 2.7%。但现在的分配下，它们几乎拿不到困难质量：在 44k，空翻、侧滚、躺/起、跳跃等组合计只拿到困难质量的 0.5%。

## Goal
- 困难质量不再被少数片段捕获：任何一个片段拿到的困难质量都不超过上限。
- 在相同迭代下，BONES-SEED 全量评测的失败数低于现有基线，同时回报不下降。

## Non-goals
- 不改 softmax 温度 25、50 / 40 / 10 的混合比例、G_b 的定义和更新方式（EMA 0.05），以及 bin 长度。
- 不处理 104k 之后的退化（等本 change 的结果出来再看），也不加速。

## Current behavior
`MultiClipMotionCommand._sample_frames`（`src/supermimic/envs/mdp/commands.py:257`）的流程：
1. `hard = softmax(−25·bin_return)`；
2. 记忆项 `bin_memory` 用 `hard` 做 EMA 更新；
3. p = 0.5 / N + 0.4·hard + 0.1·memory。

日志只有 `sampler/entropy`、`sampler/bin_return_mean`、`sampler/hard_mass_clip_end_bins`，看不出困难质量集中在哪里。

## Proposed behavior
1. **新配置 `MultiClipMotionCommandCfg.hard_clip_cap: float = 0.01`**：同一个片段的全部 bin 合计，最多拿困难质量的 1%。镜像片段按独立片段计算，所以不需要解析片段名。设为 0 时回到论文写法，即不设上限。
2. **超出部分按比例分给其余片段**（water-filling）：被截的片段按比例缩到上限，多出来的质量按原权重比例分给没超限的片段；被推过上限的片段也一并截住。这样每个片段内部 bin 之间的相对权重不变。
3. **记忆项用截后的 `hard` 更新**，被捕获的片段因此不会通过记忆项继续占份额。
4. **新日志**：
   - `sampler/hard_top_clip_share`：截前份额最大的片段拿到的困难质量；
   - `sampler/hard_eff_clips`：截后按片段汇总的有效数 1/Σm²。

## Design details
- **为什么按片段设上限，而不是改温度**：
  - 用 44k 的 `bin_return` 模拟：

    | 设计 | 有效 bin 数 | 有效类别数 | kick_back 份额 | 失败组份额 |
    |---|---|---|---|---|
    | 现状 | 2.3 | 1.1 | 94% | 0.5% |
    | 每片段 1% | 367 | 90 | 5% | 5.4% |
    | 每片段 0.5% | 912 | 126 | 3% | 4.8% |
    | 温度 15 | 501 | 121 | — | — |
    | 温度 10 | 22.5 万 | 390 | — | — |

    失败组指空翻、侧滚、躺/起、跳跃等。
  - 140k 时的模拟结果类似：每片段 1% 时有效 bin 243 个，失败组份额 2.3%。
  - 改温度会把质量大量分给长片段（body_check、舞蹈），因为它们的 bin 多。而且温度是论文明确给出的参数。
  - 上限只在出现捕获时才起作用，没有捕获时和论文写法完全相同。这属于"论文未写"的补充，要在 PROJECT.md 里注明。
- **为什么选 1%**：模拟中 0.5% 和 1% 给失败组的份额差不多（4.8% 对 5.4%），1% 离论文原本的陡峭程度更近。上限可以通过命令行调。
- **实现**：放一个纯函数 `cap_group_mass(h, group, num_groups, cap, iters)` 到 `envs/mdp/sampler_math.py`，可以在 CPU 上测试。
  - 用闭式解，不迭代：把片段质量从大到小排序，若前 k 个被截，其余片段的缩放系数是 s_k = (T − k·cap) / (T − 前 k 个之和)；取第一个满足"第 k 个片段 × s_k ≤ cap"的 k，结果是精确的。可以证明 s_k 随 k 单调不减，所以前 k 个确实都超限。整个过程约 20 个 kernel，不做 host 同步。
  - 最初的写法是固定 20 轮迭代，在 A 上实测每次调用多出 2.54 ms，主要是 kernel 启动开销，超过了 plan 的 2 ms 门槛，所以改成闭式解（10-27，T10）。
  - 当 cap × 片段数 < 1 时（例如 LAFAN1 只有 40 个片段），自动用 max(cap, 1/片段数)，退化为"片段之间均分"。
  - `library.bin_clip` 已有，可以直接用。
- **开销**：每次重置多出一次约 13 万元素的排序和一次约 100 万元素的 gather；每次迭代约 2.5 次重置，预计不到 1 ms/次。plan 里要实测。
- **断点续训**：不新增状态，旧 checkpoint 的 `bin_return` / `bin_memory` 可以直接用。
- **预期效果（如实说明）**：上限的作用是消除捕获，并把失败组拿到的困难质量从约 0.5% 提到约 5%，即困难部分给失败组的重置约增加 10 倍。但评测失败位置在训练中只是"中等难"（G 约 0.84），所以对失败数的改善可能有限，要靠实验确定。
- **验证实验（A 机）**：
  - run 名 `bones_seq_clipcap@A`。代码是主分支（含 critic 修复）加本 change。启动参数和 `bones_seq_critic_alive@A` 相同（`beyondmimic_seq`，320k 调度，每 4k 存一次 checkpoint，seed 0）。
  - 基线是同代码、无上限的 `bones_seq_critic_alive@A`：44k 166 / 0.9333，88k 70 / 0.9413。四个已有 run 的 44k 波动范围是 166–210 / 0.930–0.934。
  - 在 44k、88k、104k 做全量评测和分组统计。104k 对应论文的 3 h，论文在这里约 27 个失败。
  - 训练期间检查 `hard_top_clip_share`、`hard_eff_clips`，并核对训练回报不再出现单个片段造成的崩塌。
- **判定标准（44k 全量）**：
  - 失败 ≤ 120 且回报 ≥ 0.930：有效，跑到 104k 和论文比；
  - 失败 121–165：效果弱，在 88k 再看一次；
  - 失败 ≥ 166：无效，上限不是瓶颈。下一步录跳跃失败的视频，看失败方式。

## Edge cases
- 片段数少（LAFAN1 40 条）：自动放宽为 1/片段数。
- 一个片段只有一个 bin，而这个 bin 本身就很难：它最多拿到上限，其余质量分给别的片段。
- `sampling_mode` 为 uniform / start 时不受影响。
- 所有片段都没有超限：输出和论文写法逐位相同（测试覆盖）。

## Clarifications
- Q：下一步做什么？→ A（用户，10-27）："开两条路：1. 修改采样器 2. TF32，BF16加速"；旧的两个 critic change 先归档并合并进主分支（已完成：`57a98ce`、`0a373d5`）。
- Q：设计是否批准？→ A：用户批准（10-27，plan 模式）。

## Assumptions
- 上限默认 1%，按单个片段（镜像片段单独计）计算，未单独询问：模拟中 0.5% 与 1% 效果接近，1% 偏离论文更小。
- 实验用主分支代码（含两个 critic change）加本 change，fp32，seed 0；单种子，只能识别较大的效果（44k 已有四个 run 的失败数波动 166–210）。
- 评测失败位置在训练中是"中等难"这一判断来自 88k 一个 checkpoint（70 个失败片段）。

## Project impact
`docs/PROJECT.md` 的回报采样一节写明：每片段困难质量上限、默认值、"论文未写"、新日志键；BONES-SEED 的 Not supported 列表按结果更新。

## Experience impact
更新 `docs/experiences/training/return-sampler-clip-end-bins.md`，扩展为"困难采样被少数 bin 捕获"：片段末尾是一种，难而学不动的片段是另一种；按片段设上限；用 `bin_return` 还原分配的诊断方法。

## Open questions
- 评测失败位置在训练中只是"中等难"，原因是训练从片段中途按参考状态起步、回合短、有噪声。要把它们排到前面，可能需要另一种信号。本 change 不处理。
